# CandyOS architecture

## The three mechanisms

**1. Patch series** — for repos upstream actively develops (frameworks/base,
Settings, LatinIME, vendor/lineage, lineage-sdk, packages/modules/Permission,
plus the nine P33 launcher-icon apps: Contacts, Dialer, Messaging, Jelly,
Glimpse, DocumentsUI, Aperture, AudioFX, Stk). The repos stay as *stock*
LineageOS checkouts in the manifest; after every sync, `candyos-sync.sh`
resets each one to the plain upstream revision and replays an ordered
`git format-patch` series with `git am -3`. Patches are plain files in this
repo, so they review, diff, and merge like any other change.

**2. Vendored apps** — for self-contained KitKat-era app ports that share no
history with the app they replace. These live whole under `apps/` and are
copied into their slots after every sync. The stock project is removed from
the manifest (`manifest/candyos.xml`) so `repo sync` never resurrects it.

**3. Vendor overlays** — for content that is added to the tree without
replacing any stock project. Directories under `vendor/` are copied
verbatim into the tree after every sync (same reset-and-copy discipline as
the vendored apps, but into otherwise-unoccupied paths). Currently:
`vendor/partner_gms` (MindTheGapps 14.0.0 — the real Google
services/Play Store, see
`vendor/partner_gms/README.md` — plus Organic Maps), which plugs into the
*stock* LineageOS `WITH_GMS` hook in `vendor/lineage/config/common.mk`
(the flag itself is set by the `patches/vendor-lineage/` series), and
`vendor/candyos` — the **generated wallpaper overlay**
(`scripts/candyos-gen-wallpapers.py` from `assets/wallpapers/`:
`default.jpg` becomes the system default wallpaper by overriding
framework-res `default_wallpaper` in all three density buckets; see
`vendor/candyos/README.md`). The
partner_gms blobs are pinned downloads managed by
`scripts/candyos-fetch-apps.sh` (which extracts the MindTheGapps zips and
runs `scripts/candyos-gen-gapps-mk.py` to generate the per-arch
makefiles), not committed files; see `vendor/partner_gms/README.md` for
the details, including the arch conditionality (MindTheGapps is
arm/arm64 only, so the emulator QA images build without GApps). (The former `vendor/testing` overlay was sunset 2026-10-26 —
its test bench moved into the CandyOS Experience app's Testing menu; see
`docs/phases/TASKS.md`, Phases 23 and 25.)

## Patch series details

* Each `patches/<series>/` directory holds an ordered `NNNN-*.patch` chain
  generated by `git format-patch` — the numbering is the apply order.
* `patches/<series>/BASE` records the upstream commit the series was last
  generated against. It is informational: `git am -3` is self-contained and
  does not need the base, but BASE tells you how far upstream has drifted
  since the last refresh.
* Applying uses `git am -3` first (three-way merge against upstream drift),
  with a plain `git am` as fallback.
* The mbox `From <sha>` header of each patch is zeroed by `candyos-save.sh`:
  `git am` mints new commit shas on every replay, so patch identity is the
  content, not the sha.
* Legacy commit messages in the series use the old project's prefixes
  (`KITKAT-P<n>`, `KitKat UI P<n>:`). New commits use `CandyOS P<n>:`
  (see docs/contributing.md).

## Launcher icons (P33)

Every built-in app's drawer icon is KitKat-styled. Sources, by app:

* **Already authentic** (no change): the vendored 4.4 ports — Calculator,
  Calendar, DeskClock, Music, Sound Recorder — carry their donor
  `ic_launcher_*` PNGs, which match the reference set. CandyOS Experience
  keeps its candy mark by design (already period-styled; user direction).
* **4.4 donor assets, byte-identical** (Settings, LatinIME keyboard): the
  `settings-4.4` / `latinime-4.4` donor mipmap sets, vendored under
  `reference/donor-icons/` (the donor tree itself is local-only, per the
  rules).
* **Reference set** (Contacts, Dialer, Messaging, Jelly, Glimpse,
  DocumentsUI, Aperture): `reference/icons/*.png` — People, Phone,
  Messaging, Browser, Gallery, Downloads, Camera.
* **Re-tiled CandyOS originals** (Notes, Reminders): the existing brand art
  from `reference/originals/` re-tiled onto the reference family's tile
  geometry (rounded corners, darker border ring, soft shadow).
* **Synthesized** (AudioFX, Stk): no 4.4 counterpart exists, so
  KitKat-family tiles are drawn programmatically (Holo-dark EQ faders;
  gray SIM card).

`scripts/candyos-gen-icons.py` is the single generator: it regenerates the
vendored app PNGs repo-side and, given a tree argument, pushes the
in-tree copies (the eleven patched projects above + the two vendored
slots). Icon changes therefore flow: edit `reference/icons/` (or the
originals/donor dirs), re-run the script with the tree path, commit each
patched project (Flow B), `candyos-save.sh`, done.

Mechanism note: every replaced icon ships as legacy full-bleed density
PNGs (48/72/96/144/192) with the adaptive `ic_launcher*.xml` and its
background/foreground/monochrome drawables removed — the 4.4 behavior,
which is what keeps the art unmasked and square like the donor ports.

Accepted exceptions (rule 5 — cannot be restyled without breaking
signatures): CandyLauncher itself (prebuilt PRESIGNED Flutter APK, shows
in its own drawer as "thelauncher"), the MindTheGapps Google apps, and
Organic Maps (PRESIGNED product apps).

## History and provenance

The patch series were extracted — unchanged — from the original dev forks,
which remain on GitHub as read-only historical mirrors (with the original
`kitkat/p<n>` phase tags):

* `EHowardHill/android_frameworks_base` (branch `kitkat-mods` history)
* `EHowardHill/android_packages_apps_Settings`
* `EHowardHill/android_packages_inputmethods_LatinIME`
* the app-port forks under `EHowardHill/` for the six vendored apps

The forks are not needed to build or develop CandyOS; the canonical content
lives in this repo.

## Tree state after `candyos-sync.sh`

* Patched projects: detached HEAD at `m/lineage-21.0` (the synced upstream
  revision) plus the CandyOS patch commits on top. Never keep personal
  branches checked out in these projects — `candyos-sync.sh` resets them.
* Vendored slots: plain directories (no `.git`), exact copies of `apps/`.
* Overlay paths (e.g. `vendor/partner_gms`): plain directories (no `.git`),
  exact copies of `vendor/`.
* Everything else: untouched stock LineageOS.
